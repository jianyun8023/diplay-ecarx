## 已知问题与观察

- 用户操作的是 **iPhone「设置 → 蓝牙」关闭再打开**，之后需在手机蓝牙列表手点车机才能连接。
  这不是车机适配器开关操作；车机恢复修复不能据此宣称解决手机端行为。
- 目标为音乐走 CarPlay、蓝牙保留用于无线建连；没有扩大为禁用原生电话或改变 A2DP/HFP 策略。
- 旧日志已有麦克风读取、编码和 UDP 发送数据，但不能证明 iPhone 收到可识别的人声。
- HiCar 同时唤醒、Siri 识别、手机音乐输出选择、OEM 热点控制仍未解决或未获实车确认。
- `RETRY_DISPATCHED` 只表示调用重启入口，不表示通过内部所有门控或 RFCOMM 已连接。

## Android 手机上的初步验证

Android 手机可作为运行 Debug 应用的普通 Android 主机；它不是 iPhone 的替代品。
**source-only Debug 包默认使用本地 MFi，未附带身份资产。缺少身份时应用会停在设置阶段，
并非进入本项目 USB/无线握手后才失败。** `DiPlayActivity` 的 setupError 门控和 Host 身份加载
先于连接；Controller 成功完成 startMfi 后才调用 startPhone。
因此普通包只能先验证安装、设置界面，以及**独立于本应用**的系统热点入网、USB/OTG 设备枚举。
只有合法认证前置条件已满足，才可以验证下面的应用信任等待与端到端连接。
具体可行性还取决于手机型号、Android 版本、USB 主机/OTG 能力及网络模式；最低 Android API 为 24。

1. 记录 Android 型号/版本与 Debug 提交号；使用自己的测试 iPhone、数据线及所需的已有合法认证硬件。
2. 安装 Debug 包，通过正常系统界面批准 USB/蓝牙等必要权限；不要绕过系统授权、修改签名或使用生产配对材料充当夹具。
3. **热点**：先独立在系统设置中手动开启测试热点，确认 iPhone 能关联并获 IP。这不证明应用无线 CarPlay 链路可用。
   合法认证前置通过后，再按应用已有连接模式配置并观察连接进度、错误和诊断；不把手机热点行为当成 ECARX OEM 热点 API 验证。
4. **USB**：先独立确认 Android 主机/OTG 能枚举设备。这与应用握手不同；Android USB 访问授权也不是 iPhone「信任此电脑」。
   合法认证前置通过后，才在本应用分别观察等待、主动拒绝、锁屏、超时、拔线和手动重试；
   重枚举可能再次要求 Android USB 授权，本地 USB 网络可能需要 VPN 授权。有明确终止结果后不应自动重复弹出信任请求。
5. **蓝牙/收音**：在普通手机可观察适配器状态门控与诊断字段；不把普通手机麦克风、音频路由、蓝牙协议栈的结果外推为领克车机通过。

手机上无法替代验证 ECARX DIM 仪表/车道、方向盘键、HiCar 竞争、车机麦克风硬件路径、
车机蓝牙恢复时序或原生电话共存。不要为手机测试尝试关闭整车 HMI 包。

## 实车对照与软件检查

停车状态下对比屏幕触发 Siri 与方向盘长按，分别观察 HiCar 和实际音源/电平；
比较正常连接、iPhone 设置中蓝牙开关后自动连接、手机手点车机连接三个过程。
保存诊断前检查敏感信息，只分享必要脱敏片段。

完整软件检查继续遵循 `AGENTS.md` 的九项任务，涵盖 shared/common/home 测试、三个 lint 和三个 Debug 构建。
已知云端只有 loopback 网络接口时，基线 `ExistingWifiManagerTest` 的 14 项网络接口假设测试会失败；
应与纯基线对照，保留真实失败，不为通过而跳过或修改无关生产逻辑。
本文件不预先宣称新分支软件检查或实车验证通过。Debug 包为测试用途，不替换平台签名发布包。
