# 中控与仪表同时显示 CarPlay

在「设置 → 导航 → 亿咖通导航」打开「仪表复制中控 CarPlay（实验性）」，按提示重连。
保持「仪表导航」开启，开始导航后仪表显示中控 CarPlay 的完整画面。
默认关闭，关闭并重连后恢复独立仪表地图及原有安全区校准。

## 调研结论

- `30ca36ee`（fix36）把仪表改为 display 1 上的 `Presentation`，请求 1920×720 的
  CarPlay 独立仪表流 111；它并不是中控流 110 的副本。
- `fe83397f`（fix37）的实车记录表明：`setPresentationToDimSwitch(false)` 会关掉
  display 1 到仪表的通道。历史上“窗口已显示、仪表却没变化”的问题与此有关。
  正确顺序是先建立窗口再开启通道，退出时先关闭通道再撤窗口。
- 原有「整屏镜像到仪表」只操作车机通道，不能改变已经置顶的 `Presentation` 的视频来源。
  默认请求 111 时，iPhone / 地图应用决定两块屏幕分别显示什么；本地复制 111 不会把中控
  重新变回同一张地图。

本次复用 `AndroidMediaSink.setMirrorSurface(110, "ecarx-cluster", surface)`，为仪表建立
独立解码输出，中控保留自己的 Surface。复制模式不声明 111 / altScreen，避免 iPhone
按独立仪表模式重新分配地图。保留原来的主屏首帧门禁、导航开始/结束时机和投屏通道顺序。
模式随运行会话保存，修改设置后必须重连；Activity 重建不会偷用尚未生效的新设置。

## 使用边界

- 复制的是整个 CarPlay 画面，包括程序栏和卡片；中控切到音乐，仪表也跟随。
  不支持中控显示其他应用而仪表独立保留地图。
- 按视频原始比例居中显示，空余区域为黑色，不把 1920×944 拉伸成 1920×720。
  仪表固件在画面上叠加的车速、ADAS、裁切窗口仍须实车核验。
- 本模式没有独立仪表流，所以独立地图安全区设置、桌面地图副本和 launcher 地图共享没有图源。
  原有相关配置保留，关闭复制模式并重连后可继续使用。
- 复用两个视频解码器；目标车机的并发解码能力、延迟及持续温升需实车验证。
  没有额外申请录屏权限，也不会复制 Android 设置页或其他应用。

## 测试交接

自动测试覆盖设置保存与重连提示、主流声明、原有独立流回退、首帧门禁、复制 Surface
替换与释放、中控输出不被抢占、等比例画面，以及当前车机尺寸的设置截图。

模拟器应使用生产 `AndroidMediaSink` 与 `EcarxClusterPresentation`，向主流输入可辨认的
H.264 测试视频，检查主屏和 display 1 都有连续更新的相同帧，关闭仪表不影响主屏。
还需检查断线/重连、导航结束、Activity 重建和恢复独立流。切勿把只验证 Surface 调用
或两个独立生成的相似画面当作复制成功。

模拟器没有真实 iPhone 和原厂仪表接收端：只能验证 Android 视频复制与生命周期，不能
证明 iOS 地图行为、原车通道开关和仪表遮挡已经通过。实车须补测 Apple Maps / 实际使用
的地图应用，记录开启/关闭复制模式各一次的连接日志和两屏视频。
