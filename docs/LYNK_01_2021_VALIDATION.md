# 领克 01 2021 款：连接与语音复验

本仓库当前以领克 01 2021 款为主要适配目标。以下是待执行的实车复验，不是兼容性承诺或通过记录。软件回归流程见 [ECARX_TESTING.md](ECARX_TESTING.md)。

## 测试前

- 停车后操作，不在驾驶过程中切换连接、热点或音频设置。
- 记录 APK 版本、构建提交、车机固件与 Android 版本。旧报告缺少构建提交时，不把当前源码修复当作旧 APK 已包含。
- 固定同一手机、线缆、USB 数据口与网络环境，一次只改一个变量。
- 不删除配对、不重置手机信任、不停用整个车机 HMI，不为诊断扩大系统权限。
- 报告不包含密码、密钥或完整设备标识；默认只收集音频统计，不录制或上传语音。

## USB 信任确认

分别覆盖首次配对、已有配对、等待超过普通协议超时后确认、明确拒绝、手机锁定、等待时拔线、手动取消。

验收：

- 明确收到等待信任响应时，提示用户在 iPhone 确认，不反复重建健康的 USB/Lockdown 通道。
- 拒绝、锁定或等待期限结束后，不自动反复弹出信任请求；用户主动重试仍可用。
- 真实 USB queue 拒绝、读写错误和物理断开保持传输错误分类，不能伪装成等待信任。
- 等待期间的分段 plist 帧不能丢失或错位；取消后不能影响新连接尝试。

记录阶段、枚举变化、错误分类、是否启用 API 28 legacy queue fallback。弹窗消失与 USB 失败的先后顺序需要实车确认。

## Siri 与麦克风

固定位置、距离和说话音量，对照：屏幕直接唤醒 Siri、方向盘长按唤醒 Siri、CarPlay 通话。原厂蓝牙电话另列，不能把其 HFP/DSP 路径等同于应用的 telephony。

记录请求及实际 AudioRecord source、设备类型、采集/编码/发送计数、peak/RMS、零样本比例、削波计数，以及 HiCar 是否同时启动。设备类型不等于物理麦克风身份；UDP 发送计数不等于 iPhone 已收到或识别。

先确认有效人声和路由，再评估增益。不要默认叠加 AGC、固定大幅增益或把通话 HAL 参数无条件用于 Siri；这些仍需针对固件验证。按键回调收到事件也不等于获得排他所有权。

## 蓝牙音频与重连

记录手机实际选中的音频输出端、是否使用车载蓝牙音频模式、是否启用会话期间关闭车机蓝牙的兼容选项，以及切换的是手机还是车机蓝牙。

覆盖首次连接、开始音乐、Siri、来电、结束会话、断线重连、应用重启和两台已配对手机场景。恢复日志必须区分“开启请求已接受”和实际 STATE_ON；开启适配器也不等于已连接手机。

选择性 A2DP 路由治理仍需确认该 ROM 的 profile 角色与可用接口，不能重新启用未经验证的旧 profile 策略，或顺带切断 HFP 电话。

## 热点

在相同上游条件下分别使用原车下拉快捷开关与应用自动开启，单独导出报告。确认实际 SSID/安全配置匹配、手机获得地址，以及局域网与公网分别是否可达。

分别记录 AP 状态、地址分配、上游/DNS、蓝牙 iAP2 认证、Wi-Fi 配置交换、Bonjour/TCP 和 CarPlay 会话阶段。AP 开启不等于有公网；没有公网不等于 CarPlay 局域链路不可用。不要把蓝牙握手阶段失败直接归因于热点。

原生快捷开关背后的 OEM 服务尚需验证。只有确认真实入口、权限和状态反馈后才能讨论复用，不猜测私有 intent 或改系统网络配置。
