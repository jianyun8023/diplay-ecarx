# 合并 v0.2.22 后的实车 A/B 测试

本轮基于 dev 合并提交 `38dd06453718833d9af756089e49be1b187c2cb5`，另加本轮构建和诊断补充。
安装包位于 U 盘 `car-test-v0.2.22-20261028-release/`，根目录《测试步骤》与包目录内的本说明相同。
旧 `car-test-20261028-platform-staging` 与《测试步骤-合并前备份》属于合并前版本，保留作历史对照。
本轮只使用新目录的 A/B；源码补充及核验结果随包保存，不能将旧包的验证结果视为新包结果。

两包均为 **Release 变体、既有平台证书签名、包含同一组本地 MFi 认证资产**。
包名同为 `com.shihab.diplay.hudtest`，versionCode=101：

| 安装包 | 版本显示 | Siri 采集实验 |
| --- | --- | --- |
| DiPlay-0.2-20261028-A-platform.apk | 0.2-car-test-20261028-A | false，现有路径 |
| DiPlay-0.2-20261028-B-platform.apk | 0.2-car-test-20261028-B | true，通信采集路径 |

A/B 的功能代码、权限及认证输入相同，只改变实验输入和版本标签。A/B 可以相互覆盖安装。
旧 U 盘平台签名测试包 versionCode=100，也可以覆盖升级；不要卸载或清数据。
若车机装的是 Android Debug 证书签名的旧测试包，会提示签名冲突：先带走报告/设置，再处理旧测试包。
正式版是另一包名，设置不自动互通；测试期间退出正式版及其他投屏会话，避免同时占用麦克风和媒体。

## 出发前与上机第一步

1. 全程停车。先备份现有设置；拍下媒体后端、音频焦点、车辆蓝牙播放、蓝牙媒体让位、整机蓝牙关闭、HiCar 初态。
2. 记录车型/753 完整 ROM、Android、手机型号和 iOS、HYWebview 版本、测试时间。系统时钟不准也要记下与手机的偏差。
3. 安装 A，确认版本为 A。设置 → 诊断 → 保存诊断报告，立即导出 `00-A-安装`。
4. 查看报告：`siriCommunicationCapture=false`、`debuggable=false`，包名 `.hudtest`；`Platform signature check=0` 才表示与车机 android 平台包签名相同。
   本地证书与旧测试包一致，不等于已经证明与车机 ROM 一致。权限以报告中的实际结果为准；若不匹配或无权限，保留报告，不按“操作成功”填写。
5. 确认完整 `.txt` 能复制到 U 盘。优先 `Download/DiPlay`，以保存弹窗为准；应用目录只保留最近八份导出，要立即另存。不要只拍报告第一页。
6. 每完成下表一行立即导出，在《测试记录.csv》填写实际报告文件名、时间、现象及截图名。异常时先导出，再断开/重试。

## A：热点、USB 与蓝牙

蓝牙部分同时覆盖 USB 直连时的媒体让位与退出恢复；不假定 USB 已连接就证明蓝牙正常。
手动热点控制目前仅对 API 28 提供平台尝试；其他 API、未知状态、权限不足可以是“受限/不支持”，不得写成成功。

| 编号 | 操作 | 必须确认并记录 |
| --- | --- | --- |
| H01-A-热点开启 | 断开 CarPlay；记录原厂热点初态，在 DiPlay 手动开启已保存的热点 | 原厂设置实际 ON、iPhone 能发现并加入、无线 CarPlay 能连接分别记录。AP ON 不证明 DHCP、互联网或 CarPlay 已通。保存操作前/后报告及设置截图 |
| H02-A-热点关闭恢复 | 退出会话后，先取消一次关闭确认，再确认关闭；最后恢复原热点状态 | 取消不写入、确认后实际 OFF、再开启成功。连接中手动操作应被阻止；超时/未知不算成功。不改 SSID、密码和频段 |
| H03-A-自动热点 | 仅在已有自动热点选项可用时，退出会话、关闭 AP、开启自动热点选项，再发起一次连接 | 区分手动控制与自动启动两条路径，观察热点是否真正开启、是否要本地 ADB/系统授权；未获授权就记受限。结束后恢复原自动热点设置 |
| U01-A-USB首次连接 | 同一 iPhone 接数据口，记录授权弹窗与进入 CarPlay 的全过程 | USB 授权、iAP2/NCM 初始化、画面、触摸、音乐/导航；报告 USB permission 与实际会话。仅充电不算连接；数据线/USB 口位置人工记录 |
| U02-A-USB重连 | 正常拔插三次，逐次等前一会话退出、再接入；再测应用后台/返回 | 每次连接耗时、授权是否重复、是否必须第二次才连上、是否残留旧会话。每次异常先导出，最后正常断开再导出 |
| T01-A-蓝牙基线 | USB CarPlay 播放时先保持蓝牙媒体让位与整机蓝牙关闭均关闭 | 记录 iPhone 输出路由、原车“媒体音频/电话”和蓝牙总开关，观察音乐是否立即暂停或路由跳走 |
| T02-A-蓝牙媒体让位 | 关闭“通过车辆蓝牙播放 CarPlay 音频”和整机蓝牙关闭，仅开启媒体让位并重连；确认选中同一台已配对 iPhone | 只影响目标手机媒体，电话/总开关保留；`BT guard media` 的 profile=11、策略与回读值；听音乐并测一次通话。若无目标手机或服务/权限不可用，记受限 |
| T03-A-蓝牙恢复 | 正常结束 CarPlay，检查媒体恢复，再连接/结束三次；无线模式另补一次 | `policyRestored=true`、实际媒体连接与播放恢复分别确认。`connectRequested=true` 不是物理连接成功；pending 要保留恢复记录，不能清数据。恢复失败先导出，再用原车设置恢复 |

手动开/关热点、自动热点、USB、蓝牙媒体让位分开测试，每次只变一个选项。
不要为了测媒体让位顺手打开“关闭整个蓝牙”，那是另一条逻辑。

## Siri A/B：固定其他条件

固定同一手机、音乐应用、媒体后端、音频通道、mic source、HiCar/HY 和蓝牙设置。
先 A 后 B，不能在换包时同时更改其他设置。每次完整结束后再开始，电话和 Siri 不重叠。

| 编号 | 操作 | 必须确认并记录 |
| --- | --- | --- |
| S01-A-Siri | 用现有长按键/入口，固定时间、导航、音乐、天气、车控五类指令；再重复同一段长句至少十五秒 | 每条识别结果、请求时间；全部五秒窗口的 peak/RMS、全零/削波、实际 source/mode、路由/仲裁、退出恢复。车控本就不支持记“不支持” |
| C01-A-电话 | A 中接听/拨打共三次，分别完整结束；每次之后播音乐并触发导航播报 | 双方声音、实际手机/车机路由、音量、挂断后音乐/导航恢复，保存 iPhone 路由截图 |
| S02-B-Siri | 覆盖安装 B，确认版本 B 和 `siriCommunicationCapture=true`，重连后重复 A 的指令和长句 | 对比同一条件；峰值高于 −25 dBFS 或较 A 提升至少 10 dB 只作为候选证据，要结合真实识别结果 |
| S03-B-连续 | B 连续十次完整 Siri 会话，第五次和第十次各导出；短按原厂助手，结束五秒后再长按 Siri | 每次实际结果、是否双触发、有无 mode 残留/仲裁泄漏。`writeOk=true` 或 `accepted=true` 不证明 HAL 生效/持续获麦 |
| C02-B-电话 | B 中重复同样三次；再后台/返回、正常退出/重连 | 实验不破坏电话、声音恢复、媒体键和封面。音频 mode 应恢复到本次开始前的值，不强求为 0 |

B 无改善或出现回归时，先带走报告，覆盖回 A。实验没有默认开启，不代表已证明修复。

## 已自动采集与人工补充

新报告保留原有连接、USB、蓝牙、Siri、媒体/HY 调度、封面、方向盘键、启动/崩溃信息，另补充：

- 安装包名、是否 debuggable、与车机 android 包的平台签名匹配结果；实际麦克风/蓝牙特权/HiCar/热点相关权限与 USB 自动授权设置。
- 附着 USB 数量、VID/PID、接口数、授权状态；不记录 USB 序列号、地址和设备名。
- 固件产品/设备/构建指纹、热点能力和当前 AP 状态、蓝牙媒体/总开关相关设置。
- 最近 64 条设置操作：手动热点请求前/回调/错误类型/结束状态、HiCar 禁用/恢复及回读/错误类型、USB 授权执行结果。即使尚未启动 CarPlay，也能导出这些操作；跨 A/B 的记录各自带实验旗标和时间。

Siri 已包含请求与实际 source、route、peak/RMS、全零/削波、读取/编码/发送、mute、mode、活跃录音客户端可见性和 ECARX 仲裁/释放；不采集原始 PCM。
连接日志只保留当前加七份历史，每份约 512 KiB，过载会标记丢行；设置动作也有限额。每阶段导出，等待该动作结束后再保存，不等最后一次性导出。

仍须人工提供：iOS/车型/HY 版本、指令原文及识别结果、真实声音/路由、原厂开关与 HY/仪表截图、时间和线材/USB 口。
无 ADB 时不能完整读取系统 logcat、HAL 内部状态、其他应用录音与厂商内部实现；不可观测填“未知”，不要由调用成功推断。
不导出 MFi 资产、签名私钥、SSID/密码或原始音频。最终交回报告、CSV 和截图；两个测试 APK 只用于本机实车，不发布到公开仓库。
