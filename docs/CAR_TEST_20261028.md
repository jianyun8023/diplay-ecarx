# 车机回归验证

更新于 2026-10-29。当前 dev 已合入 Release 的热点恢复，只保留原有 Siri 采集路径；
此前的 A/B 采集对照停止使用，语音／麦克风本地自检入口已移除。
实车反馈认为原采集路径正常，本轮重点确认语音键短按触发及原车助手是否仍干扰 Siri。

## 安装与记录

1. 停车测试，备份现有设置与报告；记录安装包版本、提交、签名来源、车型、完整 ROM、iPhone/iOS 和测试时间。
2. 用同签名安装包覆盖升级，不卸载或清数据。source-only 包缺少认证身份时不能用于验证 CarPlay 建连。
3. 导出完整诊断报告；确认包名、是否 debuggable、平台签名匹配及实际权限。报告中的请求成功不代表设备已完成动作。
4. 测试语音键前关闭 HYWebview 的语音键接管，结束其他投屏会话，避免多个接收器竞争同一按键。
5. 每次异常先导出，再断开、重试或恢复原车设置；记录文件名、操作时间和实际表现。

## 回归项目

| 项目 | 操作与验收 |
| --- | --- |
| 热点正常启动 | 分别从应用启动、无线连接和手动开启进入。已开启不重复切换，确认原厂状态、iPhone 入网与 CarPlay 建连，三者分别记录 |
| 热点失败恢复 | 覆盖 Wi-Fi 初始 ON/OFF；只在明确失败后停止热点，按实际状态完成 Wi-Fi 开启再关闭，最后重试热点一次。观察实际状态，不把请求接受当作恢复成功 |
| 热点限制 | 检查权限不足、未知状态、取消、超时及已有 CarPlay 会话时的互斥。恢复终态为 Wi-Fi 关闭；全程不改名称、密码与安全配置 |
| USB | 同一数据口和线缆检查首次连接、保留线缆重连、拔插三次、信任与锁屏提示；仅充电不算成功。问题仍需实车定位 |
| 蓝牙媒体让位 | 使用同一已选 iPhone，确认音乐走 CarPlay、原车电话仍可用；退出和重连后分别检查媒体策略恢复与真实连接恢复 |
| Siri 短按 | CarPlay 连接后短按语音键，确认只唤起一次 Siri、可以识别正常指令，原车助手不抢占；重复十次完整会话 |
| Siri 生命周期 | 检查切到后台仍能短按唤起；断连后短按交还原车；长按及通话期间交给原车处理，避免同时开启两个助手 |
| 语音广播证据 | 查看 `ECARX voice short press` 的 registered、ordered、sent。可中断的有序广播才接管；普通广播保留原车处理。日志不能替代真实 Siri 表现 |
| 真实电话 | 接听与拨打，确认双方声音和挂断后的音乐、导航播报恢复；电话与 Siri 分开测试 |
| 媒体和导航 | 检查歌名、封面、暂停、上下曲与一按一次；确认 HUD、车道、仪表首帧、导航结束清理、后台接续及重连 |
| HiCar | 单独测试现有 HiCar 开关权限、请求与回读，测试后恢复初态；HiCar 开关不等于接管原厂语音助手 |

## 报告与人工补充

常规报告继续记录连接、USB、蓝牙、媒体、按键事件、麦克风环境及采集统计，不保存原始录音。
平台权限、USB 授权和附着设备、固件、热点状态及设置动作也在报告中；动作记录保留最近 64 条。
连接日志按现有轮换限额保存，每阶段都应及时另存完整报告。

需人工补充真实声音与识别结果、原车和 iPhone 路由、热点开关、HY/仪表画面、线缆和 USB 口位置。
软件回归不能替代实车验收，热点 ON 也不能证明联网或 CarPlay 已就绪。
