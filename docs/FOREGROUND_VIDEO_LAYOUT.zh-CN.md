# 保留系统栏时的前台视频布局

## 修复边界

会话画布保持不变，并不代表显示大小保持不变。旧路径把每次系统栏显隐后的窗口高度立即送入 `fit`；例如已有 1920×944 画布在 1920×880 区域中会缩成约 1790×880，再随窗口恢复而放大。这里保留系统栏变化不重建会话的保护，另修显示几何。

普通全屏 Host 在系统栏后布局，但仍按用户设置显示系统栏；根布局按**用户要求保留的系统栏的稳定 inset**留出空间，不按其他窗口临时改变的栏可见性反复收缩。视频、触摸层、黑角和菜单共享同一安全区域。没有写死车机的栏高度，没有裁剪画面，也没有强制隐藏系统栏。两栏都隐藏、多窗口和 Harman 继续使用原有窗口策略。

SurfaceView 和恢复占位图现在在同一个受控 measure/layout 阶段获得相同边界，不再在父布局回调中改子 View 的 LayoutParams。真实的窗口大小、旋转、分屏或用户设置变化仍会重新计算布局；不会永远锁住旧窗口尺寸。

已有较大画布可能在新安全区域中稳定留边，这是完整保留画面的正常 fit；新会话使用新安全区域协商。目标是消除临时系统栏显隐导致的反复缩放，不是把任意大小的窗口都强行显示成同一尺寸。

## 自动验证

- API 28：用户保留/隐藏系统栏的四种组合、19 次临时显隐、侧边导航栏、同一安全区域内的视频和触摸、多窗口与 Harman 路径。
- SurfaceView 布局：视频与占位图一致、无需第二遍布局、真实大小变化以及会话画布改变时正常重排。
- 1920×1080、正常字体的合成画面截图：`common/build/reports/foreground-layout-ui/`。截图由 Robolectric 渲染，并非车机拍摄；四角标记用于检查完整画面，不能替代实车验收。

## 停车实车验收

记录 APK 提交号，先用“状态栏显示、导航栏显示”连接 CarPlay，再重复后台/前台切换。检查：

1. 视频不随临时栏显隐反复缩小放大，四角仍可见，没有拉伸或裁切。
2. 不出现系统栏变化导致的会话重建；记录会话 attempt 与视频显示矩形，不能仅凭 attempt 不变宣称画面已修复。
3. 四角/边缘触摸、菜单手势和恢复占位图位置正确。
4. 分别检查 TextureView 与车机使用的 SurfaceView 输出；再检查用户切换栏设置、真实分屏大小改变。
5. 如 OEM 不遵守稳定 inset/edge-to-edge 语义，记录根窗口尺寸、稳定/可见 inset 和实际视频矩形，再调整兼容策略。不要用固定 880/944 或裁切掩盖。

本修复的云端测试不证明 OEM 固件上前台动画已经通过验收。
