# 默认模式诊断与日志完整性

本次调整来自 2026-11-15 的 v151 实车导出和无线 ADB 记录。保持默认日志模式，不改变音频时钟、缓冲预算、焦点策略、HUD 发布与恢复顺序，不增加 Kotlin 核心回退。

## 七项调整

| 范围 | 记录内容 | 归属与输出 |
| --- | --- | --- |
| 媒体健康 | 音视频接收/渲染、队列丢弃、写入错误、underrun、rebuffer、解码错误与恢复、未结束 worker | Rust 汇总和限频；Kotlin 提交平台事实 |
| 启动计时 | 首帧、隧道后输出采样、前后台与页面恢复 | 原生输出点提供单调时间，平台时间线按进程/控制器/代次分组；详见启动采样文档 |
| 重复与关闭日志 | 裸 iAP 收包通知去重，已知本地关闭记录 CLOSED | 复用已有去重器；错误、字段变化和异常断链保留，原异常仍抛出 |
| 报告身份 | 当前文件在前，历史文件在后；版本、PID、bootCount、logId 与文件范围 | 日志轮转保留原身份；历史缺字段写 unknown，完整导出保留历史 |
| 焦点/HUD/MQTT | 焦点请求与 abandon 实际结果、连接/重连/订阅/发布结果、SDK 返回结果 | Rust 计数；现有诊断入口按需展示；SDK 接受不等于屏幕可见 |
| 退出/恢复 | 退出时快照、媒体最终完成、蓝牙和原厂导航异步最新结果 | 分别保存时间与 owner/operationId，退出快照不被后续结果冒充 |
| 日志链路 | 排队、丢弃、写失败、关闭后拒写、刷新超时、采集断开与重连 | 导出时提供写入健康；本地 ADB 采集器另存状态和原始分段文件 |

## 默认日志预算

- 新增媒体健康摘要每个 sink 正常最多每分钟一条；首次异常可立即一条，随后仍限频。关闭时补一次摘要；有异步 worker 时再补一次最终摘要。每个短导航提示结束不会单独输出一条健康日志。
- 焦点在 sink 关闭后各输出一次摘要；MQTT/HUD 新计数只进入现有按需诊断，不逐消息打印。
- 重复正常信息复用原来的十分钟汇总。保留字段变化、错误和已有低频心跳。
- 音频 feedback 保留原 100 ms 超限判断和每条 route 十秒异常限频，只扩充已有诊断行：`maxAheadMs`、`overrunSamples`、`overrunObservedSpanMs`、`sinceNewestRxMs`。采样跨度不是连续故障时长；迟到/重复包不掩盖 RTP 接收前沿停滞。超限也不直接等于音频缓冲溢出。
- 日志文件仍采用约 512 KiB 轮转，当前文件加七个历史文件。以上预算仅描述新增应用诊断；车机系统 logcat 的体量由系统与其他应用决定。

报告中的 `pendingWorkers`、`closing`、`final` 表示统计归集阶段；`final=true` 不是蓝牙重连、外部导航恢复或所有平台资源释放的共同完成证明。焦点摘要不声称知道系统焦点持有者。HUD `physicalVisibility=unknown`，需要实车观察。

## 导出与采集

报告导出先有界刷新异步写入器，再读取文件；`observedAt` 与 `finishedAt` 是实时读取窗口，不承诺原子快照。刷新超时、写入失败和拒写均显式计数，不能把残缺导出解释为期间没有事件。设置页的大报告预览优先保留当前日志身份与末尾，保存完整报告仍保留历史。

同路径的新日志实例接管时，轮转与实际写入串行确认 owner，避免旧队列混进新会话文件。关闭仍只等待原来的 250 ms；未能归档的旧队列行计入进程级 `supersededWrites`，新会话导出也可查看。该计数代表明确的证据缺失，不能当成已经保存。

无线采集使用仓库脚本：

```sh
uv run --no-project scripts/collect_logcat.py \
  --adb /path/to/adb --serial 127.0.0.1:5555 --output /path/to/evidence
```

脚本只读取已有 logcat 缓冲，不清日志、不修改日志级别、不控制应用。每次重连另存文件，可能回放缓冲，不删除重复内容；空窗标 `possibleGap=true`。`capture-status.json` 和 `capture-events.jsonl` 保留连接结果、字节数、设备末行时间和主机最后收数时间。无新数据标 idle/awaiting-data，不把进程还活着当作仍在收到日志。连接失败后等待十五秒重试用户给定的 ADB 地址；SIGINT/SIGTERM 停止本机采集器。

## 验证边界

Rust/JVM 定向测试覆盖日志预算、异步最终统计、音轨计数重置、输出采样、前后台计时、报告身份、去重、持久退出和恢复记录；Android 原生库需验证 arm64-v8a、armeabi-v7a、x86_64 的构建及一致 JNI 导出。

2026-11-15 本地验证结果：

| 检查 | 结果 |
| --- | --- |
| Rust 单测 | 269 通过，无跳过；采集测试需本地 UDP 套接字 |
| shared 定向回归 | 覆盖 228 项；集成运行通过 227 项，换轨测试修正替身后所属 5 项复测全部通过 |
| common 日志/报告/退出回归 | 64 通过 |
| home | 14 通过 |
| ADB 采集器 | 2 通过，覆盖断开回放、拒绝连接后的重试与采集范围记录 |
| Android 原生库 | 三种 ABI 构建通过，各有 573 个 Java JNI 导出，契约一致 |

换轨测试的原替身未提供有效 `getMinBufferSize`，没有创建所断言的新 AudioTrack；补齐替身后验证旧轨尾差及新轨原点，未因此修改生产计数规则。长时间运行的日志预算通过模拟验证：一小时内每秒结束一个短音频流，59 条周期摘要加一条最终摘要。原工作区已有的启动相关改动保留，并通过原差异反向检查确认未被覆盖。

2026-11-15 已取回旧版 v151 的 audio、MediaSession、AudioFlinger、audio policy、内存、CPU、服务、窗口、显示、SurfaceFlinger、网络、UDP、蓝牙和包信息快照。该证据用于基线分析，不能冒充本次改动的设备验收。

本次提交另完成[小米 8 实测](benchmarks/default-diagnostics-mi8-2026-11-15.md)：ARM64/ARMv7 各 23 项设备测试，两轮无线连接，标准 MediaSession 音乐控制，前后台、正常退出和报告导出；用户确认音画正常。短时默认持久日志约 3.28 KB/min，新增正常健康摘要约每分钟一条。实车导航、外部恢复和长时间负载仍待验收；ADB 断开期间不声称完整采集。
