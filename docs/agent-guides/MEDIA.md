# Media ownership

Read for audio/video, codecs, capture/echo, focus, playback/artwork or shared-output lifetime changes. For SETUP, control messages and screen wire framing also read [Protocols](PROTOCOLS.md); for host/session recovery read [Session and transport](SESSION_AND_TRANSPORT.md).

These rules are part of [AGENTS.md](../../AGENTS.md). Apply its global ownership and validation rules as well. Paths in code spans are relative to the repository root.

## Routing and renderer lifetimes

- `AndroidMediaSink` owns stream routing and renderer lifetimes. It updates native receiver destinations under the video ownership lock and disconnects old routes before retiring a stream. Rust receiver routes retain decoder references; video packets and mirror references stay in Rust until fed or dropped. `VideoDecoder`, `AudioRenderer` and `AudioFocusCoordinator` own decoding, playback and focus respectively. Keep codec worker ownership and release ordering with those implementations.

## Buffered audio, scheduling and focus

- Rust `media::audio::{buffered, buffered_state}` own buffered music TCP framing, decryption, queued and inaudible fed packets, RTP/NTP anchors, SETRATE/FLUSH, feed deadlines and bounded/paced intake. `media::audio::{queue, route}` own the retained receiver-to-renderer queue, RTP backlog recovery, arrival feedback and the ordinary-audio feedback anchor with its sampleTime calculation and single-stream reply entry; buffered keeps its own reply schema. Kotlin reads the clocks once at the existing points, commits the start-callback fact and sends the returned entry. Kotlin gates platform callbacks against pause/flush/close, commits a feed only for its current generation, and destroys/wakes the buffered owner before stopping its receiver. Renderer queue access is serialized against close; clocks stay on the output worker. AAC headers/configuration/access-unit slicing and PCM/Opus processing require Rust. The AAC owner supplies ADTS/ASC primitives; `media::audio::renderer` owns LPCM/AAC/Opus dispatch, native libopus versus SDK capability selection, SDK codec-specific bytes, the input pump (10 ms dequeue / 100 ms audio budget), output draining and reusable PCM storage. JNI drives the SDK decoder; Kotlin creates/configures/closes its MediaCodec, presents diagnostics and executes hardware writes. Release each codec output before the synchronous PCM callback, including on copy failure; release exceptions retain Java finally precedence. Never keep a mutable Rust renderer borrow across a host callback: it reenters PCM processing. Direct PCM views cannot outlive that callback; the worker closes their owner after processing returns. Keep AudioTrack/AAudio, focus, route and head-unit calibration behavior.

- Rust `media::audio::scheduler` owns output accounting, playback/prebuffer state, the granted-capacity start threshold, chunk limits, write-result actions, rebuffer and tail deadlines, buffer calibration and navigation-route decisions. Its facade stays on the renderer worker, allocated lazily, reset in place and closed by worker release. Kotlin executes clock reads and actual play/pause/write/focus/route actions, reporting successful actions back to the core. Renderer compressed packets always use Rust; old Kotlin queue/recovery algorithms are test-only. Rust `media::video::selection` chooses codecs and retry/probe plans; Kotlin reports codec facts, preserves platform Char folding, executes callbacks/create/sleep, and commits retry state after the retry callback. Hardware/SDK capability fallbacks remain platform behavior.

- Rust `media::audio::scheduler` owns the audio-focus policy: channel priority (phone above assistant above media), request intents and per-channel target gains, including the transient-loss mute setting's effect and the rejection mute. Kotlin reports channel activity, the requestAudioFocus result and listener gains as facts, and retains AudioFocusRequest identity, the active output table, focus callback guards and applied-volume accounting with the platform objects. Rust `media::audio::{uplink, scheduler}` own microphone read-error/no-audio recovery budgets and navigation-prompt duck/audible/release decisions, including the existing release delays. Kotlin retains AudioRecord restart/sleep/cancellation, AudioFocusRequest identity and actual grant results, pending Runnable identity and clocks. Read-error restart counts commit only after success; no-audio counts consume each attempt.

## Microphone and echo

- Rust `media::audio::{capture, uplink}` own microphone frame residue, capture clock, per-frame echo leases, PCM sample statistics/report windows, encoding, RTP/ChaCha counters and the UDP socket. Speex C converts PCM16LE, cancels echo and writes back in the native frame; SpeexDSP is statically linked into `libdiplay_media` beside libopus. There is no Kotlin data-processing or Java socket/MediaCodec encoder fallback; native pipeline creation failure releases recorder resources and fails startup. Opus capability probes the actual native encoder. `packetizer` supplies capture/clock/MTU calibration and the wire facade, reusing `uplink::seal`. Preserve Int/Long wrapping, 48/24/16 kHz clock priority, 20/10/5 ms MTU calibration, 30 ms echo lead, 250 ms tail and -40/-15 dB suppression. Kotlin retains AudioRecord, SDK timestamp/capability facts, platform effects, start/stop/restart/cancel actions and diagnostic text. A per-id opaque `NativeMicrophone.uplinkConfig` handoff lets Rust own microphone effective-configuration compatibility and the successful-start commit: an identical committed configuration reuses the running sender, any change (port, key or format) replaces it, and the config is committed only after the new sender actually started; Kotlin executes the recorder and platform resources. An identical-key replacement snapshots and resumes the previous sender's ChaCha nonce so nonce space is never reused; a different key starts fresh. Independent packetizer/Concentus references stay test-only.

- Rust `media::audio::{routing, echo}` own audioType/channel/content/legacy-route and speaker-fallback decisions, far-end PCM/downmix/clock state and capture-clock alignment. Kotlin retains AudioTrack/AudioRecord/AEC capability facts, SDK actions and output-wrapper lifetimes; Rust capture owns its independently retained echo ring; independent old DSP algorithms are test-only. A live microphone resolves the current output's echo reference at each software-AEC frame boundary without taking sink locks, retains the new ring before releasing its old reference, and serializes reads/rebinding with capture release. Recovered renderers keep independent rings so a failed worker's late writes cannot pollute the replacement; same-rate recovery does not reopen AudioRecord or its platform effects, while an incompatible output rate attempts the existing platform-AEC fallback. Buffered anchor/feedback reply schema and NTP conversion stay with the Rust buffered owner through the bplist platform bridge.

## Video pipeline

- Rust `media::video::{pacing, flow, selection}` own input/output timing, reference chains, decoder queues/backlog, byte conversion, codec configuration and degradation. Production video requires the Rust `vpipe` NDK loop (API 28+); initialization failure is explicit, with no Java playback loop. The Kotlin worker carries only the simple `VideoControlMailbox` (FIFO, interruptible wait, close wake, shutdown drain); no frame, budget or chain-discard JNI calls remain on the production control path, and the old Java frame queue exists only as the host pipe's test double. Kotlin retains configuration/Surface requests, capability enumeration, hardware availability probes and SDK resource guards, not duplicate policy state. Keep codec retries, software fallback and vendor parameter degradation. Host SDK pipe replay is test-only and distinct from real Android receiver/FD acceptance. Rust `media::video::codec_actions` is the commit boundary for actual codec-operation results, not planned rendering: only successfully shown output counts as rendered; a failed or oversized operation stops the rest of that batch's codec buffers (they stay with teardown) while every packet already transferred into the batch is still released; the Rust planners decide what to do and the NDK codec adapter commits what actually happened.
- The first-frame and frame-sample facts cross `VideoDecoder` → `AndroidMediaSink` → `CarPlayMediaEngine` as named `VideoStreamEvent` values on the sink's per-type event handler; the frame sample's timestamp and decoder epoch are typed fields of the JNI event, and only the stream's current decoder delivers them. Diagnostic text stays formatting-only: no session behavior may parse, match or convert it.

## NowPlaying, artwork and auto-play

- Rust `session::playback` owns incremental iAP2 NowPlaying field parsing/retention and navigation renderer leases, quiet-tail expiry and aggregate route/priority decisions. Both the main-media and the Glance song projections live in that owner; the Glance counts status 1/3/4 as playing and an explicitly blank title also forgets the retained artist. Kotlin retains immutable publication DTOs, UTF-8 replacement/trim, the Glance title/artist composition with its UTF-16LE output clipping, clocks and renderer token objects. Opaque GC values require no native close lifetime; malformed fields preserve old values and a closed renderer cannot publish late playback.

- Rust `session::playback` also owns artwork track identity, recovery generations and the one-send-attempt budget, queue versions/content deduplication/cache eviction, and MediaCenter acquisition/publication decisions. Kotlin retains Handler/executor work, image references and recycling, MediaSession publication, Binder registration/calls/cleanup and uncertain-result guards. Preserve retry callback reentrancy, stale-session disposal and published-image lifetime. Commit publication only after a completed platform call for the still-current, non-uncertain session; a normal rejected publication still commits its attempted snapshot. The Kotlin facade consumes artwork queue snapshots as named results; business code no longer reads the variable-length native layout.

- Rust `session::playback` owns host auto-play duplicate activation decisions, Bluetooth waiting counts and wait/send/give-up rules. Kotlin retains the latest session reference and identity comparison, settings/SDK reads, diagnostic schedule number, Handler, cancellation and actual media commands. Claim a new session and reset its budget before reading adapter mode; disabled mode, rejected sends, exhausted waits and cancellation do not rearm the same latest session. A→B→A can claim again; adoption claims the live reference without granting another Play. Preserve 3 seconds initially and five relative 2-second deferrals: the sixth check sends if Bluetooth is off and gives up if still on, not an absolute 13-second deadline. Check shutdown/session guards before SDK reads; NowPlaying is diagnostic only. Duplicate activation must not skip the preceding Bluetooth yield. onStop does not cancel; existing session-ended/destroy cancellation and shutdown guards remain in Kotlin.

## Session isolation and shared outputs

For the last telephony lease, close the packet source, then stop the downlink output before shutting down capture and returning the communication route. Microphone cleanup can outlast the remaining playback buffer. The sink waits outside its monitor for the output worker to pause, flush and release the phone track, with a bounded wait for a stalled SDK operation.

CarPlayMediaEngine feedback and session-close cleanup must stay scoped to the requesting/closing AirPlaySession identity. Ordinary-audio metadata, pending microphone configurations and packet captures may coexist for multiple sessions in the same engine. Closing one session removes/closes only its own entries; an older session must not stop a microphone id still registered by another session. Keep engine-wide buffered-output retirement barriers, resource locks and platform cleanup ordering; this isolation does not make each session the exclusive owner of shared outputs.

The buffered shared-output coordinator has engine lifetime, separate from each BufferedAudio stream. Rust owns idle/installing/retirement-only phases, candidate cancellation, retired eligibility and installation/barrier decisions inside the existing audio owner. Kotlin keeps actual owner/transition/stream references, the original ownership lock, WeakHashMap identity entries containing opaque eligibility values, and close/cleanup-complete facts. Never replace weak eligibility with an accumulating Rust session-ID set. Preserve detach-before-close, callbacks outside the ownership lock, cancellation without early barrier release, and normal-close versus completed-cleanup as distinct facts. Cross-session replacement retires the old eligibility at begin even if the candidate is later cancelled; ordinary TEARDOWN does not retire the session. Only the matching transition can commit or release its barrier. Ordinary audio and cluster resource identities remain independent of this buffered coordinator.

Rust `media::output_lease` owns the non-buffered stream identity and output-sharing leases: each accepted audio, microphone and screen output registers a lease keyed by (engine epoch, kind, stream type, audioType) plus the holder session, and only the last release of an output identity may stop it. Kotlin acquires on each accepted stream/microphone/screen and releases at the matching removal (teardown, session close, peer EOF, replacement), using the returned last-release fact to decide whether to stop the sink output; it keeps the actual Closeable, AudioMeta, capture, CAS outcomes and resource identities. `audio::scheduler` still decides duck notification. An old teardown/close/EOF must not stop a still-registered replacement id/type; preserve the final owner's cleanup and empty-owner repeated unduck, and an unrelated old unduck cannot clear the current prompt. Teardown and session close detach and close a source stream before releasing its lease, so a final flush lands on a live renderer; only the last holder stops the shared output. A screen or data teardown never releases an audio/microphone lease, and a same-session re-SETUP stops the shared output only when it is the last holder. The lease decides who may stop an output; delivery admission is separate: when a new route takes over the same AudioStreamId, the previous audio route is permanently retired (its later packets are dropped in Rust, never handed to the switchboard) so a replaced session's still-open stream cannot feed the new output, while a renderer-failure detach stays recoverable and still falls back to the sink. Screen configuration delivery has the same admission in the engine: registering a screen type makes that stream the type's only delivery owner (the cluster diagnostic owner generalized to every screen type), so a replaced session's still-open stream — whose own registry key still names it — cannot configure the shared per-type decoder, its mirrors or the saved configuration; screen frames were already covered by native-route retirement. Audio route disconnect still permits same-stream renderer recovery, and microphone sender/config replacement remains a separate boundary.
